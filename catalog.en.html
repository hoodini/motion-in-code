Nine concepts, and then it all makes sense

No After Effects and no programming background. Each concept builds on the one before it, so it pays to read them in order.

0.1

A video is a stack of pictures

And if we can draw any picture on demand, we can make a video.

A video is a fast sequence of still pictures. Each of these pictures is called a frame. When the pictures change fast enough, the eye stops seeing separate images and sees continuous motion. How fast? That's the fps, short for frames per second. Cinema uses 24, the web usually 30, and motion graphics of interfaces 60. Why isn't 24 enough? Because a camera smears fast movement (this is called motion blur), and the smear fills the gap between pictures. A picture drawn in code is perfectly sharp, so at 24 or 30 we see it jump. At 60 the jumps are small enough, and phone screens refresh at least 60 times per second too.

›››››

The price of 60: more pictures to compute. A 30-second video at 60fps is 30 × 60 = 1,800 pictures. Every picture is made of pixels, tiny squares of a single color, and the resolution says how many there are: 1920×1080 means 1,920 pixels across and 1,080 down. The ratio between width and height is the aspect ratio: 16:9 is a landscape screen (YouTube, presentations), and 9:16 is a portrait screen (Reels, TikTok, Shorts).

And here's the insight the whole catalog stands on: to make a video, all we need is a way to draw picture number N. If we can draw any frame on demand, we can ask for frame 0, then 1, then 2, all the way to 1,799, and stitch them together. That's the whole secret of "video that is code".

0.2

A web page: three languages, three layers

Why the browser is the best drawing engine for AI videos.

Where do the pictures come from? From a web page. The browser (Chrome, for example) is a free and remarkably powerful drawing engine: it can draw text in any language, including right-to-left languages like Hebrew and Arabic, in any font, plus shapes, images, video and even 3D. And Claude writes web page code fluently, because it's the most common kind of code on the internet.

A web page is built from three languages, and each one is responsible for a different layer. The demo below has one button from the Ketzev film. Toggle each layer off and on and see what it contributes:

  • HTML says what's there on screen: "there's a button, and it says Start workout". Each such item, a button or a heading or an image, is called an element.
  • CSS says how it looks: orange, fully rounded, in the Anton font. Without CSS we get the browser's plain gray default button.
  • JavaScript (JS for short) says what happens. In our case: how the button changes over time. Without JS the button freezes.

So how does a page like this become a video file? With two free tools. Playwright is a Microsoft tool that opens an invisible browser and drives it from code: "open the page, set the time to 0.5 seconds, capture", and again and again, 1,800 times. ffmpeg is a veteran program that stitches the pictures, together with the music, into a single MP4 file. It also compresses: 1,800 full pictures weigh several gigabytes, while an MP4 file mostly stores what changed from one picture to the next and gives up tiny differences, which is why it's hundreds of times smaller. The price: fine details, like a slow color gradient, can suffer.

0.3

Library, npm and license

Why we don't write everything from scratch, and why the exact name matters.

A library is code someone else wrote, tested and shared, so we don't have to write it ourselves. Drawing a chart correctly, with axes, ticks, labels and spacing, is weeks of work. A library like Recharts does it in ten lines. npm is the world's largest registry of JavaScript libraries, and it's free: the command npm install recharts downloads the library into the project. A library packaged for npm is called a package, and it has a version number like 3.2.1. The first number goes up when the new version is no longer compatible with code written for the old one, the middle one when a capability is added without breaking anything, and the last one when a bug is fixed. That's why we specify a version: if Claude knows version 2 and the project installs version 3, some of the code might not work. (A command like this is typed in the terminal, a text window where we give the computer instructions. In practice, Claude Code types it for us.)

Why does this matter in a prompt? Because Claude knows the popular libraries well, and the right way to use them. When we write "a Recharts area chart", it knows exactly what to build. When we write just "a chart", it may improvise a homemade version that looks average. An exact name turns a vague request into a clear target.

A license is the legal permission to use the code. Every element in the catalog is marked with its license, and three types keep coming up:

  • MIT and ISC: almost anything goes, including commercial work for a client. The only condition is keeping the copyright notice in the code.
  • Apache 2.0: similar, and adds protection against patent claims.
  • CC0: public domain. No conditions at all.
A code license is not a trademark licenseThe logo file (in SVG format, which we'll meet in 0.5) can be completely free, and the logo itself is still a trademark: a name or symbol the law reserves for a company, so that nobody can present themselves as the company or as acting on its behalf. Showing a logo to say that a product works with that company's service is fine, but implying that the company endorses us is not, and most companies' brand guidelines forbid distorting or recoloring their logo. Some tools are also free only up to a certain size: Remotion, a tool for making videos from code that we'll meet in chapter 07, is free for individuals and for companies of up to three employees. Before any commercial work, check.
0.4

Components and React

Lego bricks with settings, and why they're perfect for video.

A component is a building block we can use again and again, with settings. Like a Lego brick that comes in several colors and sizes: the same button can be orange or transparent, large or small. These settings are called props. React is a library from Meta for building interfaces out of components. Instead of telling the browser "move this, color that", we describe to it what the screen should look like given the data. Every time the description changes, React compares it with the previous one and changes only what actually changed on the page.

And that's exactly what video needs. We compute the frame's data from the time ("at second 3.6, progress is 72%"), hand it to React, and it draws exactly that frame. The same input always gives the same picture. A function is a recipe in code: we put a value in (the input) and it returns a result (the output), for example time goes in and a progress percentage comes out. A function that has no hidden memory, and whose result depends only on its input, is called a pure function:

a React component that is a pure function of time
function Frame({ t }) {                       // t = the time in seconds
  const progress = Math.min(100, t * 20);     // 0% at t=0, 100% at t=5
  return <Progress value={progress} />;       // a ready-made progress-bar component
}

The progress is t times 20, but never more than 100 (Math.min picks the smaller of the two). The number goes to a ready-made component that draws a progress bar (Progress, which we'll meet in chapter 02).

0.5

Vector vs. raster

Why logos and icons need to be SVG.

There are two ways to store an image. Vector stores a description: "a circle, the center is here, the radius is this much, the color is orange". When we enlarge it, the computer redraws it from the description, so the edges stay sharp at any size. The web's vector format is called SVG. Raster stores a grid of pixels (PNG, JPG): when we enlarge it, each pixel becomes a big square, or smears if smoothing is turned on.

In motion this is critical, because the camera zooms: a 3× push-in on a logo is a 3× enlargement. In the demo, both sides show exactly the same icon. Turn up the zoom and see what happens to each one:

0.6

Three ways to draw: DOM, Canvas, WebGL

And why particles and 3D need the graphics card.

  • DOM (short for Document Object Model) is the usual way. The browser keeps every element as an object in memory, with all its styles, works out what goes where, and draws. Excellent for text and interfaces, and slow when there are thousands of elements, because each one has to be stored and computed.
  • Canvas is a blank drawing board of pixels. We give it commands ("draw a circle here") every frame, and it doesn't remember what was drawn. Very fast for thousands of shapes, but everything is on us: no automatic layout, no line wrapping.
  • WebGL is a way to draw through the graphics card (GPU). A regular processor has a few powerful cores that each work through tasks one after another; a graphics card has thousands of small cores that compute thousands of points in parallel. That's why 3D and tens of thousands of particles go through it. The three.js library makes it comfortable to use.

0.7

The clock t: why a library's animation breaks video

The rule that applies to every element in this catalog.

Most libraries animate by the wall clock: "move this over one and a half seconds of real time". In a browser that's perfect. But while capturing a video, each frame takes 100 to 500 milliseconds to capture, because for every capture the browser has to finish drawing, turn about 2 million pixels into an image file and hand it to the program doing the capturing. That's 6 to 30 times longer than the 16.7 milliseconds of live playback. Meanwhile, the library's animation keeps running in real time, and within a few frames it's already over. The video jumps.

The fix, applied in every demo on this page: turn off the library's animation and compute everything from t. Frame number i gets t = i ÷ 60, and draws whatever should be on screen at that moment. That way frame 37 is always the same picture, no matter how long it took to capture. The function that draws the picture for moment t is called seek(t). 0.8

Motion that looks real: easing and springs

Why motion at a constant speed looks robotic.

Nothing in the world moves at a constant speed: a ball speeds up as it falls, a door slows down before it closes. That's why motion at a constant speed (linear motion) looks mechanical. Easing is a curve that converts "how much of the time has passed" (from 0 to 1) into "how much of the way we've covered". It comes in three common shapes, and we'll see their names in the prompts: ease-in starts slow and speeds up, ease-out slows down at the end, and ease-in-out does both.

A spring is a curve that overshoots the target a little and comes back, like a door on a spring hinge. It has two settings: stiffness (how fast it gets there) and damping (how quickly the bounces die down: higher damping, fewer bounces). In the catalog we compute the spring with a closed-form formula: we plug in t and immediately get the position, without computing all the frames before it. That's why it obeys the t rule:

a closed-form spring: position at time t, straight from the formula
const spring = (t, w = 12, z = 0.8) => {    // w = frequency (higher = faster), z = damping, must stay below 1
  if (t <= 0) return 0;
  const wd = w * Math.sqrt(1 - z * z);
  return 1 - Math.exp(-z * w * t) * (Math.cos(wd * t) + (z * w / wd) * Math.sin(wd * t));
};
// spring(0.1) = 0.38, spring(0.2) = 0.79, spring(0.4) = 1.013 (just past the target), spring(0.6) = 1.005, then 1

How to read it: in the code, w is the stiffness (a higher number means a faster spring; technically it's the spring's frequency) and z is the damping. Math.exp(…) is the brake, a number that starts at 1 and shrinks over time, which is why the oscillation fades. cos and sin rise and fall in a smooth, repeating wave between -1 and 1, and they are the oscillation itself. (If a point's horizontal position is cos of t and its vertical position is sin of t, the point moves in a circle. That's how the circles move in several of the effects later on.) z must stay below 1, because at 1 the formula divides by zero; 0.99 means almost no bounce. When the prompts say "closed-form springs", this is what they mean. An interactive lab for playing with stiffness and damping is in the springs chapter on the method page.

0.9

How we ask: the six blocks

The skeleton every prompt in the catalog is built on.

Every prompt here is built on the same skeleton, developed by the creator zero (@twoclipping) for his launch films. A language model that doesn't get precise instructions gives us the average of what it has seen, and in motion the average is a "template": dark background, glow, particles and a fade (a transition where one picture slowly dissolves and the next one appears beneath it). The six blocks erase the average:

  • <inputs>: what Claude needs to ask us for before it starts (data, logo, music), and what to do if we don't provide it.
  • <direction>: the taste. Format, colors as exact codes, fonts by name, and a list of what's forbidden. An exact color is written like this: #FF8F3A. That's three pairs of characters: how much red, how much green and how much blue, from 00 (none) to FF (the most, 255). Lots of red, some green and a little blue make orange, and that way Claude gets exactly the shade we mean.
  • <structure>: what happens when, in beats of the music. A beat is a single pulse of the song, and tempo is measured in beats per minute (BPM). At 120 BPM: 60 seconds divided by 120 = half a second per beat. 120 is common in popular music, and the numbers come out round: one beat = 0.5 seconds = 30 frames at 60fps.
  • <build>: how to build it. This is where the t rule and the technical instructions for each library go.
  • <gotchas>: known bugs, listed up front, so Claude avoids them on the first pass.
  • <start>: a cheap approval gate. First a beat map (a list of what happens on each beat) and four stills (single pictures from the film), and only after we approve, the full film. It's cheap because four pictures are created in seconds, while rendering, producing all the frames into the final file, takes many minutes.

Library names, function names and technical terms are English anyway, so these prompts work as-is in any tool. The on-screen text inside them is whatever language the film uses: here it's English, and for a film in another language we just swap those strings. A full breakdown of each block, and why it works on a language model, is in the anatomy chapter on the method page.

01

Data and charts

The moment the film proves something: growth, results, progress.

A good launch film answers the question "Why should I believe you?", and most of the time the answer is a number. In the film for Ketzev (Hebrew for "rhythm"), a fictional fitness app, this is the moment the user sees how far they came this month. The four elements here are four ways to show a number: a line that unfolds over time, a comparison between days, one big number, and a percentage of a goal.

The library we use here is Recharts: a collection of React components for charts, which draws them as SVG (that is, vector graphics, sharp at any zoom). Under the hood it borrows parts of a library called D3 for the math: where each tick mark goes, how to smooth a curve. It's free under the MIT license, and the current version is 3. The main alternatives, and when to pick them:

  • Chart.js: draws on Canvas and doesn't need React. Fast and simple, less flexible in styling. MIT.
  • Apache ECharts: hundreds of chart types, maps included. Heavier. Apache 2.0.
  • D3: the low-level layer itself. Full control over every pixel, and a lot more code. ISC.

The rule for choosing: if the project is in React and the chart is a standard one, Recharts. If we need a shape that has no name, D3. Either way, the built-in animation is off and everything is computed from t.

Bars that land on the beat

What you see

A week of workouts. Each bar jumps up on its own beat, half a second after the one before it, overshoots its height a little and settles back. Today's bar is painted in the brand's "fire" gradient (yellow, orange, red). The days run left to right, Sunday to Saturday. (If your film is in Hebrew or Arabic, which read right to left, reverse the order so the week starts on the right.)

How it works

  • The height of each bar = its value × spring(t − beatTime), where beatTime is the moment of that bar's own beat. We subtract the beat time to give each bar its own clock that starts at zero: before its beat the result is negative, the spring returns 0, and the bar hasn't started yet. The spring overshoots 1 a little and comes back, which is why the bar "lands" instead of stopping dead.
  • The number above a bar appears only once the bar is 60% of the way up, so the number doesn't jump ahead of it.
  • Today's color comes from Cell, a Recharts component that lets each bar have its own color.
When to useComparing 4 to 12 items and highlighting one of them. Perfect for a musical rhythm, because every bar is a beat.
When not toMore than 12 bars: they get too thin to read on a phone screen, and the animation drags on too long.

Why they shake

In many fonts, for example Inter, the font the numbers here are set in, the digit 1 is narrower than the digit 8. These are called proportional digits. When the number changes every frame, its width changes, and everything around it moves. The fix is a font feature called tabular-nums: every digit gets the same width, like in a table. (This works only if the font includes such digits; Inter does.) One line of CSS: font-variant-numeric: tabular-nums.

And for the thousands separators (1,248) we use Intl.NumberFormat, the browser's built-in tool for formatting numbers the way each language writes them.

01.4

Progress ring

SVGstroke-dasharray

What you see

A ring that fills to 78% of the weekly goal, with the number counting up in the center. The ring we know from fitness apps, drawn in code, with no library at all.

Try it

Check "Show the full outline" and see that the ring is really one long dashed line.

How it works

In SVG we can turn a circle's outline into a dashed line. stroke-dasharray sets the length of the dash and also the length of the gap after it, and stroke-dashoffset shifts where the pattern starts. The trick: make the dash and the gap both as long as the whole circumference (2πr: two times pi, about 6.28, times the radius r). When we shift the dash, the gap slides into its place, and the gap is nothing, so only part of the dash stays visible:

offset = circumference × (1 − progress). When progress is 0, the whole dash sits off the circle. At 1, it covers everything. The numbers update live in the dark box. And we rotate the circle by −90°, because in SVG a circle starts at 3 o'clock, and we want it to start at 12.

When to useA percentage of a goal, a countdown, loading. A shape everyone knows from their watch and their phone.

Real UI with shadcn/ui

A product film needs an app that looks real. Here's how to get one without designing it from scratch.

The most important scene in Ketzev's film is a tour of the app: someone types, clicks, switches a tab, and we see that the product works. For it to look like a real app, we build it from real interface components. Three concepts, each one stacked on the one before:

  • Tailwind CSS is a way to write styling with classes: a class is a label we stick on an element, and the CSS decides what each label does. shadcn/ui is very popular, which is why it looks "like a real app". For the same reason, it can also look generic. Kinetic typography is text whose motion is part of the message: a word that lands hard feels important, a word that gets typed out feels like a conversation. In a launch video most of the screen is text, which makes this maybe the most important element in the catalog. The demo below runs four techniques back to back, two and a half seconds each.

04.1

Four techniques for moving text

Canvas 2DAntonRTL

SLAM: words that land

Each word appears on its own beat, starts too big and shrinks to its size with a spring, like a rubber stamp. Made for headlines of three or four words at the peak of the music.

MASK RISE: rising from a line

The words rise out of an invisible line, as if they were waiting just below it. The "line" is a mask: a rectangle that shows only what's inside it, like a stencil. The text moves and the mask doesn't, so the words look like they're born from the line.

POP TYPE: typing

Letter after letter, each one pops a little as it's typed, with a blinking cursor. The pace is uneven, like a real person typing, and every keystroke lands on a half beat or a quarter beat (what musicians call an "eighth note" and a "sixteenth note"; at 120 BPM those are 0.25 and 0.125 seconds), so the typing "plays" along with the music.

MARKER: highlighter

A strip of color stretches behind the important word, in the reading direction (left to right in English, right to left in Hebrew). The simplest way to tell the viewer "this is the word".

Right-to-left languages (Hebrew, Arabic): three things to ask forReveal words from right to left, in reading order. Wrap numbers and English words in unicode-bidi: isolate. Why? The browser lays out Hebrew right to left, and English and numbers left to right. Neutral characters like +, % and the space take their direction from their neighbors, so sometimes they wander to the other side. This setting tells the browser to lay out the wrapped piece as one sealed unit, without mixing it into the direction of the sentence. And give condensed display fonts more size: Anton is condensed (so is Karantina, our Hebrew headline font), so a headline in it can be set about 1.25× larger than one in a wider font and still carry the same visual weight.

05

3D with three.js

Phones, glass, particles, ocean. And what every word in the prompt means.

three.js is the most popular library for 3D on the web, free under the MIT license. It sits on top of WebGL (the browser's way of drawing with the graphics card) and spares us the thousands of lines of code WebGL demands. To understand a 3D prompt, it helps to think of a film set:

  • Scene: the stage, where we place everything.
  • Camera: where we look from, and how wide the view is (wide like a wide-angle lens, or narrow like a telephoto, zoom-style lens).
  • Mesh (an object): every object in the scene. It is built from two parts: Geometry, the shape itself, and Material, the surface: its color, how shiny it is, how rough it is, whether it is transparent. The graphics card can draw one thing very fast, triangles, so every shape, even a sphere, is broken down into lots of small triangles.
  • Light, and the Environment map: a 360° image of the surroundings that shows up as reflections in shiny surfaces. Without it, metal and glass look gray and dead, because metal has almost no color of its own: what we see in it is whatever it reflects, and with no surroundings it reflects nothing.
  • Renderer (the photographer): turns all of this into one 2D image, the frame.

Two more terms keep coming up in the prompts. PBR (Physically Based Rendering) means materials that respond to light according to the laws of physics, so they look real under any lighting. We control them mostly with two numbers between 0 and 1: metalness (how metallic it is) and roughness (how rough it is: 0 is a mirror, 1 is chalk). GLTF is the standard file format for 3D models, "the JPEG of 3D": a model we built in a 3D program (for example Blender, which is free and appears at the end of this chapter) or downloaded from a site comes into three.js as a GLTF file. Drag any demo here to rotate it. That works only in the preview: in the film, the angle is computed from t.

We inject a few lines into the built-in three.js shader with onBeforeCompile, and pass t to it as a variable (uTime).

05.5

three.jssum of springs

What you see

Six cards on a ring in 3D. The ring turns one step on every beat, overshoots a little and settles. This is the moment in the launch film where the click bursts into a carousel.

How it works: a sum of springs

The ring's angle is a sum: every beat has its own spring, which starts at that beat's time and adds one step (60°, because 360° divided by 6 cards is 60°). angle = Σ step × spring(t − beat_i). The symbol Σ (sigma) means "add them all up": for every beat i, which starts at time beat_i, we add its spring. Each spring overshoots the target a little and comes back, which is why every step "lands". And since this is a sum of closed-form formulas, we can compute the angle at any moment, even if we jump straight to the middle.

Each card also rotates around its own axis so it always faces the camera. Otherwise the text on the cards at the back would read reversed, as in a mirror.

05.6

3D equalizer

three.jsInstancedMesh

What you see

A 20×20 grid of bars with a wave running through it, and every beat gives it a "kick" from the center outward. The color depends on height: low bars are blue, medium ones orange, tall ones gold. Here the wave comes from a formula; in a real film the heights come from the music itself.

From the music, without breaking the clock

A live audio analyzer in the browser runs on the wall clock (real time, not the film's t), so it doesn't work for frame-by-frame capture. Instead, we analyze the song in advance: for every frame we compute the spectrum, how much energy there is in each frequency range (bass, mids, highs), and store it in a table. During capture we just read the row for t.

How it works: one shape, 400 instances

Every separate object in three.js is a separate drawing instruction that the processor (CPU) sends to the graphics card (a draw call). Thousands of these every frame slow the processor down, even when the graphics card has capacity to spare. This matters mostly for the live preview (lab 0.6); the film comes out smooth either way. InstancedMesh sends one instruction: "draw this box 400 times, here are the position and color of each one". Same image, a fraction of the work.

When to useA music video, "the music is the clock", an energetic build-up before the drop.
When not toA film without prominent music: an equalizer moving over silence looks disconnected.

What you see

A background of huge, soft blobs of color drifting slowly, with a fine grain like film. Check "No blur" and the secret is out: these are five plain circles.

How it works

We draw five large circles in the brand colors, each moving along a path made of the sin and cos of t at its own speed, and blur them all with a very heavy blur (70 pixels). On top goes a faint layer of random noise.

Why the grain matters

A video stores each color channel (red, green, blue) in 8 bits, which means 256 levels. A subtle gradient, say from navy to a slightly lighter navy, uses maybe 20 of them. Across 1,000 pixels that's 20 steps, each 50 pixels wide, and the eye sees stripes (banding). The video file's compression makes it even worse. Subtle noise breaks up the stripes, because the eye averages it into one smooth tone. This technique is called dithering.

When to useA background for a headline or an end scene, a change of mood between chapters.
When not toBehind small text or a busy interface: it lowers the contrast.

06.4

Four transitions without a fade

Canvas 2Dfloodmorphwipeiris

Why no fade

A fade (crossfade) is when one image slowly disappears and the next one appears underneath it. It's the first transition in every editing app, which is exactly why it looks like a "template". zero's rule: every scene is born from an object that's already on screen. That way the eye has something to follow instead of being cut off.

FLOOD: fill the frame

A button is pressed, and its color spreads out as a circle until it fills the whole screen. The final radius = the distance from the button to the farthest corner, so not a single sliver is left behind.

MORPH: change shape

A small pill widens, then grows taller and changes its corner rounding until it becomes a card. Width, height and corner radius each ride a spring of their own.

WIPE: sweep across

A new page enters from the right, led by a fire-gradient band. That band is what turns a plain wipe into something with energy.

IRIS: close to a dot

The screen closes into a shrinking circle until only a dot is left, and that dot becomes the dot in the YUV.AI logo. The radius shrinks on a logarithmic scale: in every equal stretch of time it shrinks by the same factor. In a 1920×1080 film it starts at 1,100 pixels, the distance from the center of the screen to a corner, so at first the circle covers everything, and it ends at 14, the size of the dot in the logo. Four equal steps: 1,100, 370, 125, 42, 14, each one 3 times smaller than the one before. Why not linear? A linear shrink removes the same number of pixels every frame: 18 pixels out of 1,100 are barely noticeable, but 18 out of 30 is more than half. So the circle hardly moves at first and then slams shut all at once, because the eye perceives changes in size as ratios, not as pixels.

When to useIn every transition between scenes. Pick by the object on screen: a button floods, a pill becomes a card, a dot becomes a logo.
When not toA transition that doesn't grow out of an object on screen looks like a cut, however polished it is.
